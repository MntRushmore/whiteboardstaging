## 4. Bugs found

### B1 — HIGH: legacy image pipeline fires on Live-related edits and its feedback image hides the echoes
- What happened: editing an echo (step 8), placing a typed math shape (step 7) and `updateShape` on the graph (step 4) each restarted the legacy idle timer; 4 s later `handleAutoGeneration` ran because `legacyShouldSkip` only covers 5 s after the last pen-up. Result: 4 `/api/generate-solution` calls on a page of pure algebra. In Suggest a full-viewport overlay with Accept/Reject appeared (`04c-graph-x2.png`, `05-units.png`); in Feedback two **full-opacity, locked, 1280x800 images** were inserted *above* the math shapes (image indexes `b0QJnhmtV`, `b0Rg8HVFV` > highest echo index `b0PelwkfV`), covering every echo (`09-after-reload.png`, `10a/10b`). After reload the `ClearFeedbackButton` is gone (`feedbackImageIds` is React state), so the student cannot remove them without unlocking shapes manually. Spec §10.3 #13 expects zero image generations on an algebra page.
- Suspects: `src/app/board/[id]/page.tsx:1449-1470` (`handleAutoGeneration` + `useDebounceActivity(…source:'user')` — any user-sourced doc change is "activity"), `src/lib/live/liveStore.ts:37-40` (`legacyShouldSkip` time window only), `src/shapes/math/MathEditor.tsx:33-40` and `src/shapes/math/MathShapeTool.ts:66` (user-sourced writes, by design), `src/hooks/useDebounceActivity.ts:41-56`.
- Fix: count only student ink as activity (in the listener, ignore entries whose changed records are all `math`/`graph`/live-meta shapes; or keep `lastInkAt` in liveStore and have `legacyShouldSkip` return true when no ink changed since the last handled burst). Insert feedback images below live shapes (or exclude live shapes from the capture *and* the overlay z-order), and mark feedback images with `meta.legacyFeedback=true` so the Clear button can find them after reload.

### B2 — MEDIUM: non-math ink is echoed, which also silences the legacy pipeline
- A 3-stroke triangle was recognized as `\Delta` with confidence ≥ 0.6 → echo "Δ" → burst handled → no legacy overlay (spec §10.3 #10 expects Live silent + legacy overlay after 4 s).
- Suspects: `src/lib/live/engine/classify.ts:163-176` (`preClassify` has no "lone symbol" rule; `isLabel` only covers letters/digits), `src/lib/live/policy.ts:60,67` (`SILENT_KINDS` = label, incomplete), `src/lib/server/live-rules.ts` `classifyKind`.
- Fix: treat a line with no digit/relation/operator and a single symbol (`\Delta`, `\triangle`, one Greek letter, `\square`) as `label` (silent) and mark the burst `unhandled` so the legacy pipeline still runs for diagrams.

### B3 — MEDIUM: chemistry feedback is invisible (no amber dot, `note` never rendered)
- `Fe+O_2 → Fe_2O_3`: engine verdict `none` (no coefficients attempted) → badge none; `render()` still writes `note="Count the atoms on each side"` (Feedback) / `"Balanced: …"` (Solve) but `MathShapeView` renders only badge + latex + resultLatex. Student sees nothing in either mode.
- Suspects: `src/lib/live/engine/index.ts:385` (`verdict: balanced ? "ok" : attempted && coeffs ? "mismatch" : coeffs ? "none" : "unknown"`), `src/lib/live/liveLoop.ts` `render()` (chem branch sets `note` with status none), `src/shapes/math/MathShapeUtil.tsx` `MathShapeView` (no `note` output).
- Fix: when `analysis.chem && !balanced && mode !== 'off'` set status `warn`; render `note` as `title` on the badge and, for Solve/`Balanced:` notes, as a small second line inside `.live-math__inner`.

### B4 — MEDIUM: moving the mode dial to Suggest never starts a check; "tap the dot" not wired
- With an existing amber `x=5`, clicking Suggest did nothing for 6 s (no `/api/live/check`, pill idle). Only re-writing the line triggered the check. The spec's "tap the dot → hint card" has no implementation: the warn badge is a plain `<span>`; `controller.requestCheck` has no UI caller (only `escalate` from `LiveHintLayer.tsx:83`).
- Suspects: `src/lib/live/liveLoop.ts` `setOptions` → `reanalyzeAll()` renders with `{quiet:true}` and never calls `startCheck`; `src/shapes/math/MathShapeUtil.tsx` `Badge`.
- Fix: in `setOptions`, when mode rises to suggest/answer, run `startCheck` for lines with `verdict==='mismatch' && hintsShown<1`; add `onPointerDown` on the warn badge that dispatches a `live:request-check` event (or reads the controller from a liveStore atom) → `requestCheck(lineId)`.

### B5 — MEDIUM: graph card overlaps its echo (placement uses the estimated echo width)
- `estimateEchoWidth` (8.5 px/char + 32) gave 83 px for `y=x^{2}-4`; KaTeX measured 129 px. `placeGraph` ran in the same write batch as the echo, so the graph landed at `echo.x + 83 + 16` and covered ~30 px of the echo (`04a-graph.png`, `04c-graph-x2.png`). Other echoes grew 100→143, 120→282 px after measurement, so `findFreeSlot` avoidance also works with wrong rects.
- Suspects: `src/lib/live/placement.ts:36-40` (`charWidth: 8.5` for 24 px KaTeX), `:88-96` (`placeGraph`), `src/lib/live/liveLoop.ts` `upsertGraph` (reads `getShapePageBounds(mathShapeId)` before the ResizeObserver in `MathShapeUtil.tsx useMeasuredSize` corrects `w`).
- Fix: bump `charWidth` to ~13 for size m (scale by size), and/or when a live math shape's `w` changes (loop already sees math updates in `onChange`) re-run `placeGraph`/`replaceEcho` for that line.

### B6 — MEDIUM-LOW: reload wipes badges (mode resets to Off, `reanalyzeAll` writes status none)
- After reload: `2 x=8 ok→none`, `x=4 solved→none`, `\text{I} ok→none`; a save is triggered 3 s after every load. Badges return only after the student picks a mode.
- Suspects: `src/app/board/[id]/page.tsx:1094` (`useState("off")`, not persisted), `src/lib/live/liveLoop.ts` `start()` → `reanalyzeAll()` + `policy.ts badgeFor(mode 'off') → 'none'`.
- Fix: persist `assistanceMode` (localStorage, like `liveSettings`) or skip `render()` in `reanalyzeAll` while mode is `off`.

### B7 — LOW-MEDIUM: clustering splits flat top strokes and high superscripts
- (a) The horizontal top bar of each `F` (h≈0 px, y = top of the stem) became its own line → two `\text { I }` echoes, one with a green ✓ (`06a-chem-feedback.png`). `shouldJoin` uses `vOverlap/smallerH` with `smallerH = max(1, 0)` and the flat bar has zero overlap; rule 2 fails because `centerDiff` (22 px) > 0.6 × median (16 px). Real ink has a few px of height, so this mostly bites T/F/7/5 cross-bars drawn at or above the stem top.
- (b) A superscript `2` (60 % size) written above the x-height was split into a separate silent label line → `y=x-4`; placing its bottom at the x-height joined it.
- Suspects: `src/lib/live/strokeClusters.ts:118-133`.
- Fix: inflate every stroke rect by `max(3, 0.1×medianH)` before the overlap tests; add a superscript rule (stroke h < 0.7×median, bottom within 0.35×median of the neighbour's top, hGap < 0.5×median → join).

### B8 — LOW: prose/`text` lines are echoed and receive verdicts
- `\text { I }` got status `ok` (identical to the previous stray line). `text` is not in `SILENT_KINDS` (`policy.ts:60`). Consider silencing `text` (or at least never badging it).

### B9 — LOW (dev only): capabilities `GET /api/live/recognize` fires twice per mount
- StrictMode double effect in `useLiveMath` (`liveLoop.start()` twice). Production unaffected; spec §10.3 #2 says once.

### B10 — LOW: cosmetic
- Pill shows "Paused" for ~1.5 s after Live is switched back on (`useLingeringStatus`).
- Graph x-tick label at the left edge is clipped ("10" instead of "-10"): `src/shapes/graph/plot.ts` tick label `textAnchor="middle"` at `x = PAD`.
- Legacy Accept/Reject bar covers the Live pill and the model badge (`04c`, `05`); Report button overlaps the tldraw style panel (`01`). Pre-existing layout, not Live.
- Server logs a client-aborted `/api/generate-solution` as `level: error … Unhandled route error` (`ResponseAborted`); should be info/warn.

### Suspected, not verified (code reading)
- Closing a graph with `×` sets `graphShapeId=null`; any later `render()` of that line (cascade from an edit above, mode switch `reanalyzeAll`) will call `upsertGraph` and re-create the card the student closed (`liveLoop.ts render()` → `upsertGraph`).
