# Whiteboard feel — QA and fixes (2026-10-02)

Branch `fix/board-feel` (from `origin/main` at `620f11a`). Scope: how the board feels and works in
every interaction — writing with a mouse, a pen and a finger; the tools; the layouts from a phone to
a monitor; Live math end to end; the Ask panel and lecture mode's bar; errors from the AI routes;
performance; accessibility basics. Persistence, sync, offline, auth, the boards home and big-board
saving belong to `fix/board-reliability`; credits/Ink belong to `feat/ink-packs` (see "Found in other
lanes" below).

## Method

- `next dev --webpack -p 3002` against the shared local Supabase (user `qa-feel@example.com`), real
  OpenRouter and Mathpix calls. Production numbers from `next build` + `next start` on the same port.
- Playwright (Chromium 1243, headless) with Playwright's iPad (gen 7) portrait/landscape, iPad Pro 11
  and iPhone 13 descriptors (`hasTouch`, `isMobile`), plus 1280x800 and 1920x1080 windows. Ink was
  the tutor's own hand engine (`layoutMath`, `src/lib/hand`) replayed as strokes: mouse moves
  densified to 2 px; pen through CDP `Input.dispatchMouseEvent` with `pointerType: "pen"` and a
  pressure curve; touch through CDP `Input.dispatchTouchEvent`. AI failures with `page.route` (500,
  429, requests that never answer). Scripts, screenshots and logs are in the session scratchpad
  (`…/scratchpad/feel/`); the key before/after screenshots are in `docs/qa-screenshots/feel-*.png`.
- The machine was shared with two other agents' dev servers, builds and test runs (load average up
  to 185 at times), so absolute timings below are noisy; every before/after pair was taken back to
  back under the same conditions.

### 1. Undo after a rub-out duplicated the tutor's readbacks — broken

Repro: write `2x + 3 = 11`; rub it out with the eraser (or select all + Delete); press Undo. Repeat.
Shapes on the page after each undo: `math:live` 1 → 2 → 3 for one line. With the select tool the
extra echoes rendered typeset beside the ink ("2x+3=11 | 2x+3=11"); after switching screens and back
the board ticked the problem statement and showed "You got it!".

Cause: the eraser / Delete removes the ink and Live's hidden echo in one user action, so Undo
restores both — the echo under the id of a line Live had already dropped. Live then wrote a second
echo for the restored ink. `rebuildFromMathShapes` turned both echoes into lines over the same strokes.

Fix (`src/lib/live/liveLoop.ts`, `strokeClusters.ts`): a restored echo is taken back by its line when
the line still exists without one (`restoredEcho`); a line that needs an echo first adopts an orphan
echo already on its ink (`adoptOrphanEcho`, keeping a model's note) and deletes any extra; a rebuild
gives a stroke to one line only and deletes a second echo on the same ink, so boards already saved
with duplicates mend on open. Tests: `liveLoop.undo.test.ts` (4 cases, all failing before),
`strokeClusters.test.ts`. Browser after: 1 → 1 → 1 echo, no false tick.

### 2. Lines were read while the pen was down — broken (feel), and costly

Repro: write three lines at a slow writer's pace (strokes ~350 ms apart, each taking 200–500 ms).
Before: 19 recognize calls for 3 lines (9, 4, 6), and line 2 was read as `2x = 0` from the first
half of its 8, ringed, then re-read and ticked. After: 3 calls (1 per line), no flips.

Cause: the 600 ms quiet gate started at a pen-up and ran out whatever the pen was doing; a stroke in
progress is not complete ink, so the line was read without it (the spec says "never render while the
pen is down").

Fix (as reworked after review, R2): when the gate runs out while the draw tool is drawing a stroke
(`editor.isIn('draw.drawing')`) it looks again 150 ms later instead of reading; the stroke's pen-up
re-arms it as before. Only the stroke being drawn counts, so a stroke left unfinished (Esc, a tool
switch) or dragged later never holds the line back, and a drawing's pen-up still keeps the gate's
deadline. Test: `liveLoop.penDown.test.ts`.

### 3. Boards opened on the selection arrow — broken on iPad

Repro: open any board on an iPad; write with the Pencil. Before: a selection rectangle, no ink (the
tool at open was `select`). After: `initialState="draw"`; the tool at open is `draw`, verified with
mouse, pen and touch. (The onboarding tour already switched to the pen; ordinary boards did not.)

### 4. Phone-width toolbar off screen — broken on a phone

an iPad's board narrowed by the Ask panel. After: below tldraw's TABLET_SM breakpoint the strip moves
to the top-right corner (tldraw's SharePanel slot, `screenStripSlot`), the bar's controls wrap under

`feel-before-layout-phone-390.png`, `feel-after-layout-phone-390.png`.

### 5. Ask on an upright iPad — broken

Repro: iPad 820x1180, open Ask. Before: the panel docked at the side (the `md:` breakpoint), leaving
the 16:9 board 428x241 px with the toolbar clipped under the panel, and the text box took focus so
the on-screen keyboard came up. After: the panel docks beside the board only in landscape

`feel-before-layout-ipad-portrait-820-chat.png`, `feel-after-layout-ipad-portrait-820-chat.png`.

### 6. Stalled check / solve streams — stuck

Repro: `page.route` holding `/api/live/(check|solve)` open. Before: the pill stays "Checking…" /
"Solving…" until another check replaces it. Cause: `streamLiveSse` had no timeout (the server pings
every 15 s and ends at maxDuration, but a stalled connection never ends). After: 45 s without a byte
(`SSE_IDLE_TIMEOUT_MS`, three missed pings) aborts the request; the pill shows "The tutor took too
long to answer" with Retry. Tests in `clients.test.ts` (silent mid-stream, never answers, pings keep a
slow stream alive) and `errorView.test.ts`.

### 7. Ask request that never answers — stuck

Repro: `page.route('**/api/live/chat', () => {})`, send a request. Before: "Thinking…" and a disabled
Send after 8 s, 60 s, for ever; the message stayed in the session's history. After: 60 s
(`CHAT_TIMEOUT_MS`, past the route's 45 s maxDuration; own AbortController, not
`AbortSignal.timeout`, which iPadOS 15 lacks) → "The tutor took too long to answer. Try again." with
Retry. 500 and 429 were already handled ("Something went wrong. Try again." / "Try again in 20 s.").
Tests in `chatView.test.ts`.

### 8. Two pens at once when the dial goes up from Off — janky

Reported by the film session (`main-offsug-2-turned-to-suggest.png`): Off → Suggest (or Solve) on a
column with a slip drew the ring and the right next step simultaneously for about a second.
`setOptions` re-rendered the ring (`reanalyzeAll`) and wrote the step
(`checkMismatchesAfterLadderRise` → `suggestNextStep`) in the same tick, each with its own writer.
Fix: a line's mark says when its pen lifts (`syncMark` marks it busy; the writer's onDone, or a write
that needed no writer, calls `markDone`), and `suggestNextStep` waits for it (`afterMark`; never more
than 4 s). Test: `liveLoop.dial.test.ts` (Off → Suggest and Off → Solve; the step's first stroke now
comes after the ring's last, 864 ms earlier before).

### 9. Chrome over the screen on laptops and monitors — confusing

Repro: 1280x800 or 1920x1080. The screen was fitted with a 16 px gap; fitted by height, its top-left
(where a student starts writing) sat under the help tabs and its bottom middle under the toolbar.
Before: frame 49–751 px at 1280x800 (tabs end at 52, toolbar starts at 744); 16–1064 at 1920x1080.
After: vertical gap 64 px — frame 64–736 and 64–1016. iPads (fitted by width) are unchanged. Cost
(corrected after review; the first version of this report said "up to ~10 %", which was wrong):
wherever the screen is fitted by height it loses 96 px of height, i.e. 96 / (board height − 32) — 4 %
at 1280x800 (fitted by height only just), 9 % at 1920x1080, 13 % at a 789 px tall laptop window,
and it would have been 27 % on a phone on its side (358 → 262 px tall at 390). Since `f23fea7` the gap
follows the board's height (`screenViewPadding`): 64 px from 640 px up, 16 px at 400 px and below,
in proportion between, so a landscape phone keeps its 358 px and laptops are unchanged.
Screenshots: `feel-before/after-layout-monitor-1920.png`.

### 10. No way to delete a screen — confusing

The strip had ‹ › and + only, and the page menu is hidden: a screen added by mistake stayed for good.
After: with more than one screen the strip has a Delete button; the screen and its ink go, the one
before it is shown, and an 8 s toast offers Undo, which restores the page, its shapes and bindings
directly (not through the undo stack, which may by then hold new strokes). Tests in

Screenshot: `feel-after-screen-delete-1-toast.png`.

### 11. Three-row bar on an upright iPad — confusing

At 820 px the bar wrapped to three rows (the controls dropped under the back button, and it reserved
180 px for tldraw's old style panel). After: one row (controls wrap beside the back button, 72 px
reserved for the pen swatch, "Report a bug" icon-only below 1024 px).
Screenshot: `feel-before-layout-ipad-portrait-820.png`.

### 12. Keyboard focus invisible — accessibility

Tabbing through the board: the screen strip, the pill's "…" and its Retry/Dismiss had no focus
indicator at all (tldraw sets `outline: none` on everything in its container); shadcn buttons had a
3 px ring of light grey at 50 % (about 1.4:1 on white). After: a 2 px near-black ring (the platform
pages' focus colour, 3.8:1) on the board's controls and in the Ask panel; tldraw's own buttons keep
their blue ring. Icon buttons all had accessible names (checked: none unlabelled). Esc closes Ask,
the pen style popover and the lecture consent.

### 13. iOS double-tap zoom, small menu target — polish

The board root now has `touch-action: manipulation` (double tap on the bar's buttons cannot zoom the
page; pinch was already stopped by tldraw's `gesturestart` handler; the canvas keeps its own `none`).
The pill's 24 px "…" takes taps up to the pill's edges. Not verifiable in Chromium: needs a real iPad.

### 14. Live's clustering compared every pair of strokes — slow on very dense screens

Repro: production build, 1280x800, a screen holding 3,000 strokes (copies of real saved strokes),
15 new strokes drawn with Live on. Before: 45.6 fps, 44 long tasks, the longest 575 ms, worst frame
550 ms, worst input-to-frame latency 510 ms — with Live off the same board drew at 60 fps. A CPU
profile put ~375 ms per pen-up in `flush`, nearly all in `clusterStrokeGroups`' all-pairs loop (it
runs at every flush, for the whole screen).

Fix (`src/lib/live/strokeClusters.ts`): every join rule needs the two strokes within
max(centerFactor, barReachFactor, superRaiseFactor, dotReachFactor) medians of each other vertically,
so strokes are swept top to bottom and each stops looking once the next starts further down. Union-find
makes the order of the joins irrelevant, so the groups are identical: checked against the old loop on
722 pages (every corpus problem in all four hands, four problems a page, plus the 300- and 3,000-stroke
boards; 54,953 strokes). `clusterStrokeGroups` 317 → 58 ms for 3,000 strokes, 5 → 2 ms for 300.
Browser after (two runs, machine loaded): 37–125 long tasks but the longest 77–167 ms, worst frame
83–200 ms, worst latency 39–87 ms (from 575 / 550 / 510). Offline and drawings scoreboards unchanged.
At a realistic screen (≤ 500 strokes) none of this was ever visible.

### 15. Esc to close a panel dropped the pen — broken for keyboard users

Repro: with the pen, open the colour popover (or start a lecture and see the consent note) and press
Esc. Before: the popover closed and the tool became the selection arrow; the next stroke drew a
selection box. Cause: tldraw's key handler sits on its container and takes Esc as `editor.cancel()`,
and the draw tool's idle state answers cancel with `setCurrentTool("select")`; our handlers closed the
panel but let the event through (the consent's React handler runs after tldraw's container listener).
Fix: both stop the Esc they consume. After: the tool stays `draw` in both cases.

### 16. The lecture bar over the toolbar's undo row — confusing

Below tldraw's TABLET breakpoint the toolbar has a second row (undo, redo, delete, duplicate). The
lecture panel sat at 80 px from the bottom and covered that row for the whole lecture on an upright
iPad. After: 112 px there (`raised`); measured on 820x1180, panel bottom 1068, the row's top 1082.
Screenshot: `feel-after-lecture-ipad-raised.png`.

### 17–20. Not fixed

- **tldraw console noise.** Every touch on the canvas logs "Unable to preventDefault inside passive
  event listener invocation" (tldraw's React `onTouchStart`/`onTouchEnd` call `preventDefault`, and
  React registers touch listeners as passive) and "Ignored attempt to cancel a touchend event…"; the
  text tool logs `[tiptap warn]: Duplicate extension names found: ['textDirection']`. Both are inside
  tldraw 4.2; nothing in this repo triggers them. No app errors or React warnings were logged in any
  other flow of the matrix.
- **Lecture's browser recognizer.** Without `ELEVENLABS_API_KEY` locally the token route answers 503
  and lecture falls back to the browser's speech recognizer; headless Chromium never starts it, so
  the bar stays on "Starting the microphone…" (Cancel works; Esc cancels the consent). No timeout was
  added: on a real device the microphone permission prompt can legitimately take longer than any
  timeout. ElevenLabs' own connect timeout (10 s) is in place.
- **iOS keyboard over the Ask sheet.** Not testable without an iPad or the iOS simulator. The sheet is
  `46dvh` inside a `position: fixed; inset: 0` root; please check on a device that the text box stays
  above the keyboard.
- **Lecture consent on a phone** covers the toolbar's undo row while it is open (it is a question
  with two buttons, answered in a moment); left as is.
- **Also seen, not changed:** the 6 s recognize timeout fired a few times under this machine's load
  (the dev server took up to 6 s to answer); the chip and the pill offered Retry each time. tldraw's
  zoom: Shift+1 zooms to the ink rather than the screen, and there is no visible "fit" control —
  pinch out (or Ctrl/⌘-scroll) returns to the whole screen. Text typed within a few milliseconds of
  placing a text box (automation only) can land out of order; at human speed it does not.

## Found in other lanes (not changed here)

- **Reliability / auth:** submitting the login form before the page has hydrated (a fast tap on a slow
  connection) does a native GET to `/login?email=…&password=…` — the password lands in the URL,
  history and server logs. The form needs `method="post"` (or no native submit before hydration).
- **Reliability / persistence:** opening a board with no changes shows "Saving…" and writes a save
  within a few seconds of load (seen on every open in the layout runs).
- **Reliability / home:** the boards home fetches `credit_summary` 3–5 times and `user_settings` and
  the boards list twice per load in dev (partly StrictMode).
- **Ink packs:** the Ask panel's "Each request uses 3 credits." and `CHAT_CREDITS` are untouched.
- **Environment:** the shared local Supabase answered one `GET /api/live/recognize` with 401 after
  21.7 s under load, and some recognize calls took 6 s (the client's timeout) — local stack contention.
